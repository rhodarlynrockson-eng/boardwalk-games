
# Boardwalk Games — User Stories

## Project Overview

Boardwalk Games is a board game shop and café. The website aims to showcase the business, provide useful information to customers, and encourage visits to the physical shop.

## User Stories

The initial user stories are based on the Code Institute Boardwalk Games guided project. Two additional user stories will be developed as part of the Game Library planning challenge.

### User Story 1 — Responsive Website

**Priority:** Must-have

**User Story**

As a website visitor, I want the Boardwalk Games website to work on different screen sizes, so that I can browse it easily on my phone, tablet or computer.

**Acceptance Criteria**

1. The website displays correctly on mobile, tablet and desktop.
2. Navigation is accessible across different screen sizes.
3. Text, images and other content adjust to the available screen width.

**Development Tasks**

1. Build the page structure using semantic HTML.
2. Use Bootstrap's responsive grid system.
3. Implement responsive navigation.
4. Test the website at different viewport sizes.


### User Story 2 — Game Images and Descriptions

**Priority:** Must-have

**User Story**

As a potential customer, I want to see images and descriptions of the games and activities available at Boardwalk Games, so that I can decide whether I would enjoy visiting the shop.

**Acceptance Criteria**

1. The website displays clear, relevant images.
2. Games and activities have informative descriptions.
3. Images are responsive across different screen sizes.
4. Images include meaningful alternative text for accessibility.

**Development Tasks**

1. Select appropriate images for the website.
2. Create sections showcasing games and activities.
3. Add descriptions explaining what is available.
4. Use Bootstrap to make images responsive.
5. Add descriptive alt text and test the layout.


### User Story 3 — Location and Contact Information

**Priority:** Must-have

**User Story**

As a potential customer, I want to find the shop's location, contact details and opening hours, so that I can plan my visit and contact the business if necessary.

**Acceptance Criteria**

1. The website clearly displays the shop's location.
2. Opening hours are easy to find.
3. Customers can find contact information.
4. Contact details are readable on mobile, tablet and desktop.

**Development Tasks**

1. Create a contact information section.
2. Add the shop's address and opening hours.
3. Include appropriate contact details.
4. Style the section using Bootstrap and custom CSS.
5. Test the layout on different screen sizes.

### User Story 4 — Booking Enquiry Form

**Priority:** Must-have

**User Story**

As a potential customer, I want to submit a booking enquiry through the website, so that I can ask about attending an event or activity at Boardwalk Games.

**Acceptance Criteria**

1. The website provides an accessible booking enquiry form.
2. Customers can enter their name and contact details.
3. Customers can provide information about their booking enquiry.
4. Required fields are clearly identified and validated.
5. The form is responsive on mobile, tablet and desktop.
6. Customers receive clear confirmation when their enquiry has been successfully submitted.

**Development Tasks**

1. Create the booking enquiry form using HTML.
2. Add appropriate labels and required fields.
3. Apply Bootstrap form styling.
4. Implement form validation.
5. Connect the form to the submission method provided in the guided project.
6. Create or configure a confirmation page.
7. Test the form with valid and invalid inputs.


### User Story 5 — Event Pricing and Student Discounts

**Priority:** Should-have

**User Story**

As a potential customer, I want to see event prices and information about student discounts, so that I can plan my visit and decide which activities suit my budget.

**Acceptance Criteria**

1. Event prices are clearly displayed.
2. Information about available student discounts is easy to find.
3. Pricing information is readable on mobile, tablet and desktop.
4. Any conditions attached to discounts are clearly explained.

**Development Tasks**

1. Create an event pricing section.
2. Add the prices provided in the project materials.
3. Include information about student discounts where applicable.
4. Style the information using Bootstrap and custom CSS.
5. Test the section on different screen sizes.


### User Story 6 — Customer Testimonials

**Priority:** Could-have

**User Story**

As a potential customer, I want to read reviews and testimonials from previous visitors, so that I can learn about their experiences and feel more confident about visiting Boardwalk Games.

**Acceptance Criteria**

1. The website includes a customer testimonials section.
2. Testimonials are clearly presented and easy to read.
3. The section is responsive on mobile, tablet and desktop.
4. Testimonials are genuine or clearly identified as fictional examples used for the guided project.

**Development Tasks**

1. Create a testimonials section using semantic HTML.
2. Add the testimonial content supplied for the guided project.
3. Style the section using Bootstrap and custom CSS.
4. Ensure the text is accessible and readable.
5. Test the section across different screen sizes.


### User Story 7 — Newsletter Sign-up

**Priority:** Could-have

**User Story**

As a Boardwalk Games customer, I want to subscribe to a newsletter, so that I can receive updates about upcoming events, new games and special offers.

**Acceptance Criteria**

1. The website provides a newsletter sign-up form.
2. Visitors can enter their email address.
3. The email field uses appropriate HTML validation.
4. Visitors are clearly informed what they are signing up for.
5. The form is responsive on mobile, tablet and desktop.
6. A successful submission displays an appropriate confirmation.

**Development Tasks**

1. Create a newsletter sign-up section using HTML.
2. Add an email input with an associated label.
3. Apply Bootstrap form styling.
4. Add appropriate validation.
5. Connect the form to a working subscription service if required by the project.
6. Test the form and its responsive layout.


### User Story 8 — Game Library Page

**Priority:** Must-have

**User Story**

As a Board Game Enthusiast, I want to browse a selection of games available at Boardwalk Games, so that I can discover new games and decide which ones I would like to try or buy.

**Acceptance Criteria**

1. The website has a separate Game Library page.
2. The page displays four new games and four old favourites.
3. Each game card includes a title, image, description, number of players and recommended age range.
4. The page uses Bootstrap cards and a responsive grid.
5. The Game Library page is accessible through the website navigation.

**Development Tasks**

1. Create a new HTML page named `games.html`.
2. Add a Game Library link to the navigation.
3. Create sections for four new games and four old favourites.
4. Build eight Bootstrap game cards.
5. Add relevant game information and images.
6. Test the page on mobile, tablet and desktop.


### User Story 9 — Game Reservation Form

**Priority:** Should-have

**User Story**

As a Board Game Enthusiast, I want to request a reservation for a particular board game on a specific date, so that I can plan my visit and have a better chance of playing my preferred game.

**Acceptance Criteria**

1. A game reservation form is available on the Game Library page.
2. Customers can select one of the eight listed games.
3. Customers can enter their name and contact information.
4. Customers can select their preferred reservation date.
5. Required fields are clearly labelled and validated.
6. The form is responsive on mobile, tablet and desktop.
7. Customers receive confirmation that their reservation request has been submitted.

**Development Tasks**

1. Add a reservation form to `games.html`.
2. Create a dropdown containing the eight listed games.
3. Add name, email and preferred date fields.
4. Use appropriate HTML input types and labels.
5. Style the form using Bootstrap.
6. Configure the submission method used in the guided project.
7. Test form validation, submission and responsiveness.
